# HGhubX v2.2.11

本仓库在上游 v2.2.10 上的补丁版：修复部分 VPN / TUN 代理下「线路检测全部失败」的问题。官方站点接口本身可用，不必再重装 2.2.10。仅发布已签名 Android APK，可覆盖安装 2.2.10 / 2.2.9 / 2.0.0。

## 修复
1. **线路探测补上 AliDNS DoH 回退**：v2.2.10 只有拉图片 / 分片时会在系统 DNS 失败后回退公网 DNS；「检测」和业务接口走的 `POST /api/public/request` 没有这条路径。部分网络下 rustls 握手收到明文（`InvalidContentType` / `corrupt message`）时，11 条线路会一起失败。现在探测与业务请求在连接 / TLS / DNS 失败时会重建客户端并回退一次 DoH（已配置 HTTP 代理时不绕过代理）。
2. **严格安全模式遇到 Clash 等内网解析时改为回退，而不是直接全线判失败**：默认严格模式只放行 FakeIP `198.18.0.0/15`（及 `198.19`）。Clash Meta / 部分 TUN 增强模式常把域名解析到 `172.19.x.x`，客户端会在发出请求前报「禁止访问普通内网」，所有线路显示失败。现在这类错误也会走 DoH，改用真实公网地址（流量仍可走系统 VPN/TUN）。

## 安装与兼容提示
- Android 标准版按 ABI 提供已签名 APK（`versionCode=2002011`），签名与本仓库 v2.2.10 相同，可直接覆盖，收藏和观看记录保留。
- 若设备上是上游或其他渠道的 HGhubX（同包名但签名不同），需要先卸载再装。
- 本次未发布 iOS / 桌面包，也未升级到上游 v3.0.0（3.0 改为导入视频源，首次启动要导入源）。
- 升级后若仍失败：先到设置临时关闭「严格安全模式」再检测；或把 Clash Fake-IP 网段设为 `198.18.0.0/15`；也可先关掉 VPN 试一次。设置里可导出网络诊断。

## 验证
- 本地 `cargo test --lib`：`124 passed; 0 failed; 5 ignored`；`check-version-sync` 与代码尺寸预算通过。
- 实网核对主站与截图镜像的 `/api/public/request`（HTTP/1.1 与 HTTP/2）均可返回有效片单；旧入口 `/api/edge/request` 仍为 503「接口已停用」。
